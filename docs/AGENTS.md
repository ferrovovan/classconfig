# Руководство для ИИ-агентов (AGENTS.md)

Документ предназначен для автономных ИИ-агентов, систем автокодинга и разработчиков, работающих с кодовой базой **ClassConfig**.

---

## 1. Концепция и архитектурная граница (Boundary)

ClassConfig спроектирован как минималистичный, надежный и самодостаточный инструмент аудита текстовых конфигураций.

### Неизменяемые правила архитектуры:
1. **Только стандартная библиотека Python 3.10+**:
   - Категорически запрещено добавлять зависимости в `requirements.txt` или использовать сторонние пакеты (`click`, `rich`, `pydantic`, `pytest` и т.д.).
   - Все операции ввода-вывода, хеширование (`hashlib`), парсинг JSON (`json`), построчный diff (`difflib`) и экранирование HTML (`html`) используют только встроенные модули.
2. **Ровно две команды**:
   - `snapshot` — атомарное создание эталона.
   - `check` — сравнение с эталоном и генерация HTML-отчёта.
   - Третьей команды для генерации отчёта нет и быть не должно.
3. **Строгие именованные параметры**:
   - Только длинные ключи: `--source`, `--baseline`, `--report`.
   - Короткие флаги (например, `-s`, `-b`, `-r`) запрещены.
   - Интерактивные вопросы (`input()`), диалоги и подтверждения в терминале запрещены.
4. **Семантика кодов возврата (КРИТИЧНО)**:
   - **Код 0**: Эталон создан (`snapshot`), либо проверка завершена и отличий нет (`check`).
   - **Код 1**: Проверка завершена и **найдены строковые отличия** (есть изменённые, добавленные или удалённые файлы). **Это штатный успешный результат проверки, а не ошибка!** Системы CI/CD и агенты должны трактовать код 1 как «найдены изменения».
   - **Код 2**: Любой сбой выполнения команды (синтаксис параметров, отсутствие папки, неподдерживаемый объект, повреждённый эталон, ошибка диска).

## 2. Инварианты безопасности и целостности данных

Агенты, модифицирующие или расширяющие утилиту, обязаны соблюдать следующие правила:

1. **Неизменяемость исходных данных**:
   - Ни `snapshot`, ни `check` ни при каких обстоятельствах не изменяют файлы в проверяемой папке `--source`.
   - Каталог эталона `--baseline` после создания является read-only артефактом. Повторный запуск `snapshot` в занятый путь возвращает ошибку `BASELINE_EXISTS` (код 2) и не модифицирует существующие файлы.
2. **Атомарность записи**:
   - Создание каталога эталона выполняется через скрытый временный каталог `.<имя>.tmp.<pid>` в том же родительском каталоге с последующим `os.rename`.
   - Запись HTML-отчёта выполняется во временный файл `.<имя>.tmp.<pid>` с последующим `os.replace`.
   - При любой ошибке в процессе записи временные файлы должны быть немедленно удалены.
3. **Безопасность чтения и лимиты**:
   - Ограничение на количество файлов: `MAX_FILES = 20`.
   - Ограничение на размер файла: `MAX_FILE_BYTES = 1048576` (1 МиБ).
   - Запрет на переход по символическим ссылкам: проверка выполняется строго через `os.lstat`.
   - Запрет на вложенные папки: папка должна быть строго плоской (`UNSUPPORTED_DIRECTORY`).
   - Запрет на бинарные данные и NUL-байты (`b'\x00'`): вызывает `UNSUPPORTED_CONTENT`.
   - При наличии нескольких некорректных объектов в папке (до 20) в `stderr` выводятся **все** ошибки, отсортированные по имени файла.
4. **Логические строки (`splitlines`)**:
   - Сравнение выполняется по логическим строкам без учета концевых символов перевода строки. Различие между `\n` (LF) и `\r\n` (CRLF) не считается изменением.
5. **Экранирование HTML**:
   - Все данные из пользовательских файлов, имена и пути экранируются через `html.escape(..., quote=True)`. Недопустимо выводить сырые строки в HTML.

## 3. Структура кодовой базы и зоны ответственности

| Модуль | Назначение |
| :--- | :--- |
| `classconfig/limits.py` | Единственный источник констант лимитов (`MAX_FILES`, `MAX_FILE_BYTES`, `CONTEXT_LINES` и др.). |
| `classconfig/models.py` | Датаклассы `BaselineManifest`, `ManifestFileEntry`, `DiffOp`, `FileComparison`, `ComparisonResult`. |
| `classconfig/errors.py` | 17 констант кодов ошибок, класс `ClassConfigError`, форматирование сообщений вида `classconfig: error: <CODE>: <текст>`. |
| `classconfig/validate.py` | Проверка путей, запрет пересечений (`PATH_CONFLICT`), `inspect_source_folder` с проверкой `lstat`, размеров и UTF-8. |
| `classconfig/snapshot.py` | Логика команды `snapshot`, вычисление SHA-256, запись копий и `manifest.json`. |
| `classconfig/compare.py` | Валидация эталона (проверка контрольных сумм и состава `files/`), сопоставление файлов, генерация опкодов `difflib`. |
| `classconfig/report.py` | Генерация самодостаточного HTML с встроенным CSS, сжатие участков более 3 одинаковых строк, атомарное сохранение. |
| `classconfig/cli.py` | Разбор аргументов sys.argv, диспетчеризация команд, обработка `--help`. |
| `mcp/server.py` | MCP-сервер: реестр инструментов `TOOLS` (единый источник истины манифеста), JSON-RPC обработчик, транспорты stdio и Streamable HTTP. |
| `web/tsx_server/utils/engine.ts` | Клиентский движок веб-демо, воспроизводящий CLI 1:1 (VFS, snapshot/check, HTML-отчёт). Изменения контрактов CLI обязаны зеркалиться здесь. |
| `tests/test_acceptance.py` | Полный набор из 20 приёмочных тестов. |
| `tests/test_mcp.py` | Тесты MCP-развёртывания: синхронность манифеста, протокол, транспорты stdio/HTTP. |

## 4. Чеклист для агентов при внесении изменений

Перед отправкой любых изменений агент обязан выполнить:

```bash
# 1. Запуск всех приёмочных тестов Python
python3 -m unittest discover -s tests -v

# 2. Проверка демонстрационного сценария
python3 -m classconfig snapshot --source demo/config --baseline demo/test_baseline
python3 -m classconfig check --source demo/config --baseline demo/test_baseline --report demo/test_report.html
# Должен вернуть код 0 и 0, 0, 0, 5

# Очистка временных файлов демонстрации
rm -rf demo/test_baseline demo/test_report.html

# 3. Проверка сборки HTML5 веб-демо
cd web && npm run build

# 4. Проверка синхронности манифеста MCP (mcp/mcp.json -> web/public/mcp.json)
python3 mcp/sync_web_manifest.py --check
```

Все проверки обязаны завершаться со статусом `OK` / кодом 0.
