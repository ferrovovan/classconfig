**АРХИТЕКТУРА И ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ**

**ClassConfig**

*Локальная утилита снимка текстовых настроек, сравнения с эталоном и HTML-отчёта*

| Поле | Значение |
| :---- | :---- |
| Продукт | ClassConfig, консольная утилита Python |
| Назначение документа | Нормативная спецификация продукта |
| Дата | 29 октября 2026 года |
| Среда приёмки | Одна машина Ubuntu 22.04 LTS или виртуальная машина с этой системой |
| Стек | Python 3.10+ и стандартная библиотека. Сторонние пакеты не используются |
| Объём | Ядро продукта: три функции, две команды |

**Как читать этот документ**

Разделы 3 и перечень приёмочных проверок обязательны для реализации. Раздел 2 объясняет состав системы и потоки данных. Если пояснение и нормативное правило расходятся, выполняется правило раздела 3\. Всё, что не названо в этой спецификации, в поставку не входит.

Главная боль, которую закрывает система: после эксперимента пользователь видит в одном отчёте, какие файлы выбранной папки изменены, добавлены или удалены, и какие именно строки отличаются от сохранённого эталона. Сравнение показывает отличия и не устанавливает причину сбоя.

**1\. Декомпозиция требований**

Архитектура переводит сценарий «сохранить папку, сравнить, открыть отчёт» в одну локальную программу из двух команд. Отдельного сервера, учётных записей и базы данных в продукте нет.

**1.1. Функциональные требования**

**1.1.1. Три функции продукта как действия системы**

Пользовательский путь состоит из пяти шагов: выбрать папку, сохранить эталон, изменить настройки, запустить сравнение с путём к HTML-отчёту, открыть отчёт в браузере. Программа выполняет первые четыре действия двумя командами. Браузер пользователь открывает сам; веб\-сервер не запускается.

| Функция | Система принимает | Система делает | Система возвращает |
| :---- | :---- | :---- | :---- |
| 1\. Сохранение эталона | Путь к папке и путь к новому каталогу эталона | Проверяет ограничения, копирует байты поддерживаемых файлов, записывает список имён и время | Каталог эталона и краткий текст в stdout. Код 0 |
| 2\. Сравнение с эталоном | Путь к текущей папке и путь к уже созданному эталону | Сопоставляет файлы только по имени и делит их на четыре статуса. Для изменённых строит построчное сравнение | Сводка статусов в stdout. Код 0, если отличий нет; код 1, если отличия есть |
| 3\. Формирование отчёта | Путь к HTML-файлу. Выполняется той же командой, что и сравнение | Собирает один самодостаточный HTML: дата, сводка, различия «было — стало», оговорка о смысле отчёта | Файл отчёта на диске. Содержимое папки и эталона не меняется |

Команды называются snapshot и check. Команда check одновременно сравнивает и записывает отчёт. Третьей команды для отчёта нет.

**1.1.2. Пользовательские истории и критерии приёмки**

| История | Системный результат | Проверка |
| :---- | :---- | :---- |
| Сохранить папку до эксперимента | В каталоге эталона лежат те же байты файлов и manifest.json со временем создания | Побайтовое совпадение копий. Повторный snapshot в тот же путь завершается кодом 2 и не меняет уже записанный эталон |
| Увидеть изменения после эксперимента | Четыре статуса: без изменений, изменён, добавлен, удалён. У изменённого файла есть построчное «было — стало» | Учебный сценарий: 1 изменённый, 1 удалённый, 1 добавленный, 3 без изменений. После ручного возврата файлов повторная проверка даёт ноль отличий |
| Сохранить понятный отчёт | Один HTML открывается с диска, спецсимволы видны как текст | Строка с символами \<, \> и & отображается как текст. Вверху отчёта есть оговорка, что подтверждается только совпадение папки с эталоном |

**1.1.3. Границы продукта: что реализуется**

•  Одна программа, один процесс, одна машина, одна папка за запуск, один выбранный эталон за запуск.

•  Только обычные файлы UTF-8 в корне выбранной папки. Не больше 20 объектов в папке и не больше 1 048 576 байт на файл.

•  Эталон и отчёт располагаются вне проверяемой папки.

•  Четыре статуса по точному имени файла и построчное сравнение текста.

•  Один HTML-файл без сервера, со встроенной вёрсткой и экранированием текста.

•  Явная ошибка, если объект нельзя честно сравнить. Такой запуск не считается успешной проверкой.

•  Поставка: каталог с программой, README и учебной папкой demo/config из пяти файлов.

**1.1.4. Что сознательно не входит в поставку**

Следующие возможности есть у аналогов или выглядят как лёгкое расширение. На главную боль первой недели они не влияют и в реализацию не входят.

•  Вложенные каталоги, символические ссылки, двоичные файлы, файлы больше 1 МиБ.

•  Распознавание переименования и переноса. Переименованный файл получает статусы «удалён» и «добавлен».

•  История снимков, ветки, откат и команда восстановления.

•  Фоновый мониторинг, расписание, слежение за папкой.

•  Сравнение прав, владельца, времени изменения и других атрибутов.

•  Проверка работоспособности программ, разбор смысла полей конфига, советы по исправлению.

•  Сеть, учётные записи, база данных, лицензия, оплата, установка на несколько машин, права root.

•  Графический интерфейс, бот, веб\-приложение и интерактивные вопросы в терминале.

**1.1.5. Нефункциональные требования**

| Тема | Требование |
| :---- | :---- |
| Время отклика | Снимок и проверка папки из 20 файлов по 1 МиБ каждый завершаются не дольше чем за 5 секунд на учебной машине. Прогресс не выводится: для этого объёма команда просто возвращает результат. |
| Приватность | Сеть не используется. Содержимое файлов не печатается в stdout и stderr. Полный текст попадает только в копию эталона и в HTML-отчёт. Демонстрационные файлы несекретные. |
| Безопасность чтения | Программа не переходит по символическим ссылкам внутри папки и не открывает их цель. Содержимое файлов не исполняется. В HTML текст конфига попадает только после экранирования. |
| Целостность эталона | Повреждённая или неполная копия — ошибка эталона. Она не превращается в статус «изменён» или «без изменений». |
| История | Программа хранит ровно тот эталон, путь к которому указал пользователь. Предыдущие снимки сами не ведутся. Новый снимок — это новый путь. |
| Повторяемость | Одинаковые байты файлов дают одинаковые статусы и одинаковые различия строк. От запуска к запуску меняются только метки времени. |
| Права | Для демонстрации достаточно прав обычного пользователя на чтение папки, запись эталона и запись отчёта. |

**1.2. Ограничения и границы данных**

**1.2.1. Внешние ограничения**

•  Сторонних API, ключей, облака и лимитов внешних сервисов нет.

•  Единственная зависимость выполнения — интерпретатор Python 3.10 или новее со стандартной библиотекой на Ubuntu 22.04.

•  Оборудование уже есть: компьютер с Linux или одна виртуальная машина. Новые лицензии и серверы не требуются.

•  Приёмочные проверки ссылок, границ каталогов и атомарной замены файла выполняются на Ubuntu. Запуск только на другой системе эти проверки не закрывает.

**1.2.2. Форматы, объёмы и жизненный цикл**

| Данные | Формат и предел | Что происходит после команды |
| :---- | :---- | :---- |
| Проверяемая папка | Каталог без вложенных каталогов. До 20 записей. Каждая запись — обычный файл UTF-8 размером до 1 048 576 байт включительно | Команды папку не изменяют. Пользователь сам редактирует настройки между snapshot и check |
| Эталон | Каталог: manifest.json и подкаталог files с копиями байтов. Описание — JSON UTF-8 | Хранится, пока пользователь сам не удалит каталог. Повторный snapshot в тот же путь запрещён |
| Отчёт | Один файл .html, UTF-8, со встроенным CSS и без JavaScript | Пишется только после успешного сравнения. Повторный check по тому же пути заменяет файл отчёта |
| Память процесса | До 20 МиБ исходных байтов плюс такие же копии эталона и текст отчёта | После завершения процесса не сохраняется |

Пустой файл длиной 0 байт считается допустимым текстом UTF-8. Пустая папка допустима: в эталоне будет пустой список файлов.

Имена с точкой в начале входят в проверку наравне с остальными. Отбор по расширению не делается. Смысл полей вроде PORT программа не разбирает: для неё это текст.

**2\. Проектирование архитектуры**

Достаточна одна локальная программа. Отдельный сервер увеличил бы поставку и не нужен ни одной из трёх функций.

**2.1. Компонентный состав**

| Часть | Решение | Почему этого достаточно |
| :---- | :---- | :---- |
| Клиент | Интерфейс командной строки. Две команды, длинные параметры, без коротких флагов и без вопросов пользователю | Целевой пользователь умеет выполнить две команды по инструкции. Окно браузера нужно только чтобы открыть уже готовый файл |
| Логика | Один процесс. Модули вызывают друг друга обычными функциями и передают объекты в памяти | Параллельных пользователей, очереди и сети в сценарии нет |
| Хранилище | Файлы эталона и один JSON-манифест. Отдельной СУБД нет | Состояние — это список до 20 текстов и время создания снимка |
| Вычисления | Локально, модуль difflib. Моделей и внешних алгоритмических сервисов нет | Нужно точное построчное сравнение, а не оценка сходства |

Состав каталога поставки:

classconfig/

  \_\_init\_\_.py       версия пакета

  \_\_main\_\_.py       запуск: python3 \-m classconfig

  limits.py         неизменяемые пределы

  models.py         манифест, результат сравнения, строки различий

  errors.py         коды ошибок и тексты

  validate.py       правила путей и файлов

  snapshot.py       запись эталона

  compare.py        статусы и построчный diff

  report.py         сборка HTML

  cli.py            разбор команд и порядок вызовов

demo/config/        пять учебных файлов

tests/test\_acceptance.py

README.md

Запуск выполняется из корня распакованного архива. Установка через pip не требуется.

**2.2. Архитектурная схема и потоки данных**

Направление данных одностороннее: от аргументов командной строки к файлам. Общей шины и обратных вызовов по сети нет.

Пользователь

    \|  snapshot \--source \--baseline

    \|  check \--source \--baseline \--report

    v

CLI (cli.py)

    \|

    v

Валидатор (validate.py) \----ошибка----\> stderr, код 2

    \|

    \+-- snapshot \--\> Запись эталона (snapshot.py)

    \|                    \|

    \|                    \+--\> \<эталон\>/manifest.json

    \|                    \+--\> \<эталон\>/files/\<имя\>

    \|                    \+--\> stdout, код 0

    \|

    \+-- check \----\> Чтение эталона и папки

                         \|

                         v

                    Сравнитель (compare.py)

                         \|

                         \+--\> HTML (report.py) \--\> файл отчёта

                         \+--\> stdout, код 0 или 1

**Поток snapshot**

1\.  CLI разбирает \--source и \--baseline. Лишний или пропущенный аргумент даёт INVALID\_ARGUMENTS и код 2\.

2\.  Пути приводятся к абсолютным. Эталон не должен совпадать с папкой и не должен лежать внутри неё. Папка не должна лежать внутри будущего эталона.

3\.  Если в папке больше 20 записей, команда сразу завершается с TOO\_MANY\_FILES. Иначе каждая запись проверяется до создания эталона.

4\.  Если есть хотя бы одна ошибка, каталог эталона не создаётся, сообщение уходит в stderr, код возврата 2\.

5\.  Если ошибок нет, программа пишет временный каталог в том же родительском каталоге, переносит в него копии и манифест и только затем переименовывает временный каталог в путь эталона.

6\.  В stdout печатается краткая сводка. Код возврата 0\.

**Поток check**

1\.  CLI разбирает \--source, \--baseline и \--report.

2\.  Проверяются границы путей: отчёт и эталон вне проверяемой папки, отчёт вне каталога эталона, родитель отчёта существует.

3\.  Читается и сверяется эталон. Расхождение манифеста и копий — BASELINE\_CORRUPT, код 2, файл отчёта не создаётся и не заменяется.

4\.  Читается текущая папка теми же правилами, что и при снимке. Любой неподдерживаемый объект или ошибка чтения останавливает команду до записи отчёта.

5\.  Имена сопоставляются как строки. Содержимое сравнивается по логическим строкам.

6\.  HTML пишется во временный файл рядом с путём отчёта и заменяет цель через переименование. В stdout печатается сводка и оговорка.

7\.  Код 0 — отличий нет. Код 1 — отличия есть, и проверка при этом успешна. Код 2 — проверка не выполнена.

Валидация стоит до записи. Преобразование текста в статусы и строки diff происходит в памяти. Сохранение делает только snapshot (эталон) и успешный check (отчёт). Команда check не записывает ничего в проверяемую папку и в эталон.

**2.3. Модель данных**

Отдельной схемы базы нет. Ниже — объекты, которые программа хранит на диске или держит в памяти до конца процесса.

**Сущности и связи**

•  Один запуск snapshot создаёт один эталон одной папки.

•  Один эталон содержит от 0 до 20 копий файлов. Ключ копии внутри эталона — имя файла.

•  Один запуск check связывает одну текущую папку, один эталон и один отчёт.

•  Отчёт никем повторно не читается как вход программы. Следующая проверка снова читает папку и эталон.

•  Несколько эталонов могут лежать рядом как разные каталоги. Программа их не индексирует и сама между ними не выбирает.

**Манифест эталона**

Файл \<эталон\>/manifest.json, кодировка UTF-8, json.dumps(..., ensure\_ascii=False, indent=2) и перевод строки в конце файла. Поля files отсортированы по имени по возрастанию кодов Unicode.

{

  "version": 1,

  "created\_at": "2026-10-29T13:48:00+07:00",

  "source\_path": "/home/user/demo/config",

  "encoding": "utf-8",

  "limits": { "max\_files": 20, "max\_file\_bytes": 1048576 },

    "files": \[

    {

      "name": "app.ini",

      "size\_bytes": 25,

      "sha256": "64 шестнадцатеричных символа в нижнем регистре"

    }

  \]

}

| Поле | Обязательность | Правило |
| :---- | :---- | :---- |
| version | Обязательно | Целое число 1\. Другое значение — BASELINE\_CORRUPT |
| created\_at | Обязательно | Непустая строка времени с часовым поясом, точность до секунды |
| source\_path | Обязательно | Абсолютный путь папки на момент снимка. При check сверять его с \--source не нужно: пользователь передаёт папку явно |
| encoding | Обязательно | Строка utf-8 |
| limits.max\_files | Обязательно | Число 20 |
| limits.max\_file\_bytes | Обязательно | Число 1048576 |
| files | Обязательно | Массив. Пустой массив допустим |
| files\[\].name | Обязательно | Имя файла без пути. Уникально внутри массива |
| files\[\].size\_bytes | Обязательно | Целое число фактических байтов копии, от 0 до 1048576 |
| files\[\].sha256 | Обязательно | SHA-256 байтов копии. Нужен, чтобы отличить повреждение эталона от правки в проверяемой папке |

Неизвестные дополнительные поля при чтении игнорируются. Отсутствие любого обязательного поля, повтор имени или несовпадение копии с size\_bytes и sha256 делает эталон непригодным.

**Копия файла**

Путь копии: \<эталон\>/files/\<имя\>. Содержимое — те же байты, которые прошли проверку. Права, владелец и время исходного файла не переносятся. Режим создаваемого файла — обычный режим текстового файла текущего пользователя.

**Результат сравнения (только в памяти и в HTML)**

| Поле | Правило |
| :---- | :---- |
| checked\_at | Время проверки с часовым поясом, точность до секунды |
| source\_path, baseline\_path | Абсолютные пути этого запуска |
| baseline\_created\_at | created\_at из манифеста |
| files\[\].name | Имя файла |
| files\[\].status | Одно из: unchanged, changed, added, deleted |
| files\[\].diff | Пусто у unchanged. У остальных — список операций сравнения строк |
| errors | При успешном сравнении пусто. При непустом списке отчёт не пишется |

Операция различия содержит вид equal, delete, insert или replace и два списка строк: как было в эталоне и как стало в папке. У equal списки совпадают. У delete заполнена только сторона эталона. У insert — только сторона папки.

**Правила целостности**

•  Имя файла уникально внутри одной папки и внутри одного эталона.

•  Ключ сопоставления при проверке — точное имя. Содержимое на выбор пары не влияет.

•  В files/ лежат только файлы, перечисленные в манифесте, и нет лишних записей и вложенных каталогов.

•  Каталог эталона после успешного snapshot либо полный, либо, при ошибке записи, отсутствует по конечному пути.

•  Успешный отчёт записывается целиком. Прерванная запись не оставляет на месте старого отчёта частично записанный новый файл: замена делается переименованием временного файла.

**3\. Техническая спецификация**

**3.1. Контракты команд**

Протокол обмена — аргументы процесса, текст в стандартных потоках, код возврата и файлы. HTTP нет.

**3.1.1. Команды**

python3 \-m classconfig \--help

python3 \-m classconfig snapshot \--help

python3 \-m classconfig check \--help

python3 \-m classconfig snapshot \--source \<папка\> \--baseline \<новый-каталог\>

python3 \-m classconfig check \--source \<папка\> \--baseline \<каталог\> \--report \<файл.html\>

Коротких параметров нет. Значений по умолчанию у путей нет. Интерактивного ввода нет.

•  \--help любой команды печатает справку в stdout и завершает процесс с кодом 0\.

•  Запуск без аргументов печатает ту же общую справку в stdout и завершается с кодом 2: работа не выполнялась.

•  Неизвестная команда, неизвестный параметр и пропущенный обязательный параметр: код 2, INVALID\_ARGUMENTS в stderr.

**3.1.2. Коды возврата**

| Код | Когда |
| :---- | :---- |
| 0 | snapshot создал эталон. Либо check успешно завершён и отличий нет |
| 1 | check успешно завершён, и есть хотя бы один файл со статусом «изменён», «добавлен» или «удалён». Это успешная проверка, а не сбой |
| 2 | Команда не выполнена: аргументы, пути, чтение, неподдерживаемый объект, повреждённый эталон или ошибка записи |

**3.1.3. Текст успешного snapshot**

Ровно эти строки в stdout, пути абсолютные:

Эталон сохранён.

Папка: \<source\>

Эталон: \<baseline\>

Файлов: \<число\>

Создан: \<created\_at\>

**3.1.4. Текст успешного check**

Ровно эти строки в stdout и при нуле отличий, и при найденных отличиях:

Проверка завершена.

Изменён: \<c\>

Добавлен: \<a\>

Удалён: \<d\>

Без изменений: \<u\>

Отчёт: \<report\>

Отчёт подтверждает только совпадение выбранной папки с эталоном.

**3.1.5. Формат ошибки**

Каждая ошибка — отдельная строка stderr. Содержимое файлов в строку не подставляется.

classconfig: error: \<CODE\>: \<текст\>

Если в папке несколько непригодных объектов и их общее число не больше 20, печатаются все такие ошибки в порядке имён. Команда всё равно завершается одним кодом 2\.

| Код | Условие | Текст после кода |
| :---- | :---- | :---- |
| INVALID\_ARGUMENTS | Неверная команда или параметры | краткая причина разбора аргументов |
| SOURCE\_NOT\_FOUND | Пути папки нет | папка не найдена: \<путь\> |
| NOT\_A\_DIRECTORY | Путь папки или эталона для check существует, но это не каталог | путь не является папкой: \<путь\> |
| PATH\_CONFLICT | Папка, эталон и отчёт совпадают или лежат друг внутри друга | пути папки, эталона и отчёта пересекаются |
| PARENT\_NOT\_FOUND | Нет родительского каталога эталона или отчёта | родительский каталог не существует: \<путь\> |
| BASELINE\_EXISTS | Конечный путь эталона уже занят файлом или каталогом | каталог эталона уже существует: \<путь\>. Укажите новый путь |
| BASELINE\_NOT\_FOUND | При check пути эталона нет | эталон не найден: \<путь\> |
| BASELINE\_CORRUPT | Манифест, состав files/ или хеш копии не сходятся | эталон повреждён или неполон: \<что именно\> |
| TOO\_MANY\_FILES | В папке больше 20 записей | в папке больше 20 объектов: \<число\> |
| UNSUPPORTED\_DIRECTORY | Среди записей есть каталог | вложенные каталоги не поддерживаются: \<имя\> |
| UNSUPPORTED\_SYMLINK | Запись является ссылкой | символические ссылки не поддерживаются: \<имя\> |
| UNSUPPORTED\_TYPE | Не обычный файл: сокет, fifo, устройство | поддерживаются только обычные файлы: \<имя\> |
| FILE\_TOO\_LARGE | Размер больше 1 048 576 байт | файл превышает 1 МиБ: \<имя\> |
| UNSUPPORTED\_CONTENT | Байт NUL или байты, которые не декодируются как UTF-8 | файл не является текстом UTF-8: \<имя\> |
| READ\_ERROR | Операционная система не дала прочитать файл или каталог | не удалось прочитать: \<имя или путь\> |
| WRITE\_ERROR | Не удалось записать эталон или отчёт | не удалось записать: \<путь\> |
| REPORT\_IS\_DIRECTORY | Путь \--report указывает на каталог | путь отчёта является каталогом: \<путь\> |

**3.2. Алгоритмы**

**3.2.1. Постоянные параметры**

Пределы записаны в limits.py и продублированы в манифесте. Пользовательского файла настроек нет: иначе предел можно было бы снять без явной смены версии продукта.

| Имя | Значение |
| :---- | :---- |
| MAX\_FILES | 20 |
| MAX\_FILE\_BYTES | 1048576 |
| ENCODING | utf-8 |
| MANIFEST\_VERSION | 1 |
| MANIFEST\_NAME | manifest.json |
| FILES\_DIR | files |
| Контекст равных строк в отчёте | 3 |

**3.2.2. Проверка одной записи папки**

1\.  Получить сведения о записи через lstat, не переходя по ссылке.

2\.  Ссылка — UNSUPPORTED\_SYMLINK. Каталог — UNSUPPORTED\_DIRECTORY. Не обычный файл — UNSUPPORTED\_TYPE.

3\.  Имя обязано совпадать с собственным именем пути и не быть пустым. В имени нет разделителей каталога.

4\.  Если размер больше 1 048 576 байт, вернуть FILE\_TOO\_LARGE и не читать файл целиком.

5\.  Прочитать все байты. Ошибка ОС — READ\_ERROR.

6\.  Байт NUL — UNSUPPORTED\_CONTENT.

7\.  Декодирование UTF-8 со строгой проверкой. Неудача — UNSUPPORTED\_CONTENT.

8\.  Иначе запись принята. Для эталона сохраняются эти же байты и SHA-256 от них.

Обход записей — без рекурсии. Порядок сообщений об ошибках — сортировка по имени. При числе записей больше 20 сразу возвращается одна ошибка TOO\_MANY\_FILES.

**3.2.3. Запись эталона**

1\.  Сначала полностью проверить папку. При любой ошибке ничего не создавать по конечному пути.

2\.  Если конечный путь эталона уже существует, вернуть BASELINE\_EXISTS.

3\.  Создать временный каталог в том же родительском каталоге. Имя начинается с точки, содержит pid и не совпадает с конечным именем.

4\.  Записать files/\<имя\> и manifest.json во временный каталог. Поле created\_at вычисляется в момент успешной проверки, непосредственно перед записью.

5\.  Переименовать временный каталог в конечный путь.

6\.  При любой ошибке после создания временного каталога удалить его и вернуть WRITE\_ERROR или более точный код, если он уже известен. Конечный путь при такой ошибке отсутствует.

Аварийное завершение процесса посреди записи может оставить временный каталог. Он не считается эталоном. Следующий snapshot в конечный путь по-прежнему допустим, если конечный путь свободен. Отдельной команды очистки нет.

**3.2.4. Чтение эталона при check**

1\.  Прочитать manifest.json как UTF-8 и JSON-объект.

2\.  Проверить обязательные поля и version \= 1\.

3\.  Для каждого элемента files проверить имя, наличие обычного файла files/\<имя\>, совпадение размера и SHA-256.

4\.  Убедиться, что в files/ нет лишних имён и нет каталогов.

5\.  Любое расхождение — BASELINE\_CORRUPT. До записи отчёта дело не доходит.

**3.2.5. Сопоставление и сравнение строк**

1\.  B — множество имён из манифеста. S — множество имён принятой текущей папки.

2\.  Для имени из B и S прочитать текст копии и текст текущего файла.

3\.  Разбить оба текста методом splitlines() без сохранения символов перевода строки. Сравнение идёт по логическим строкам.

4\.  Равные списки строк дают статус unchanged. Различие перевода строки LF и CRLF и наличие или отсутствие перевода строки в самом конце файла отдельным отличием не являются.

5\.  Неравные списки дают статус changed. Операции строить через difflib.SequenceMatcher.get\_opcodes().

6\.  Имя только из S — added. Имя только из B — deleted.

7\.  Пары по похожему содержимому не искать. Переименование остаётся парой статусов deleted и added.

Пробелы в начале и в конце строки значимы. Регистр значим. Порядок файлов в результате — сортировка по имени внутри каждого статуса, а в сводной таблице отчёта порядок статусов такой: изменён, добавлен, удалён, без изменений; внутри статуса имена отсортированы.

**3.2.6. Сборка отчёта**

1\.  Собрать HTML в памяти из результата сравнения.

2\.  Каждое имя, путь и фрагмент строки конфига пропустить через html.escape(..., quote=True).

3\.  Записать байты UTF-8 во временный файл в каталоге будущего отчёта и заменить цель через os.replace.

4\.  Если путь отчёта — существующий обычный файл, он заменяется. Если это каталог, код 2 и REPORT\_IS\_DIRECTORY, ещё до сравнения можно вернуть эту ошибку.

5\.  Родительские каталоги программа не создаёт.

Длинный непрерывный участок равных строк длиннее трёх сжимается: в таблицу попадают первая и последняя строки участка, а между ними одна строка «строки \<i\>–\<j\> без изменений». Участки из трёх и менее строк показываются целиком. Строки добавленного и удалённого файла показываются целиком: весь файл и есть отличие.

**3.3. Интерфейс**

Точки входа: терминал и один локальный HTML-файл. Отдельных экранов ввода и ожидания нет, потому что команда не задаёт вопросов и для учебного объёма не показывает прогресс.

**3.3.1. Состояния терминала**

| Состояние | Что видит пользователь |
| :---- | :---- |
| Вход и пустой запуск | Справка: две команды, обязательные пути, пределы 20 файлов, 1 МиБ, UTF-8, без вложенных каталогов и ссылок. Код 2, если аргументов не было |
| Справка по запросу | Тот же текст справки. Код 0 |
| Ожидание | Пока команда работает, новые строки не печатаются. Успешный учебный запуск укладывается в 5 секунд |
| Успех снимка | Пять строк из раздела 3.1.3. Код 0 |
| Успех без отличий | Семь строк из раздела 3.1.4, все три счётчика отличий равны нулю. Код 0 |
| Успех с отличиями | Те же семь строк, ненулевые счётчики. Код 1\. Подробности только в HTML |
| Ошибка | Одна или несколько строк classconfig: error: ... в stderr. Отчёта нет, нового эталона нет. Код 2 |

**3.3.2. Макет справки**

ClassConfig — снимок текстовых настроек и отчёт различий.

 

Команды:

  snapshot \--source ПАПКА \--baseline НОВЫЙ\_КАТАЛОГ

  check \--source ПАПКА \--baseline КАТАЛОГ \--report ФАЙЛ.html

 

Папка содержит только обычные файлы UTF-8: не больше 20 файлов

и не больше 1 МиБ каждый, без вложенных каталогов и ссылок.

Эталон и отчёт сохраняются вне этой папки.

Отчёт подтверждает только совпадение папки с эталоном.

**3.3.3. Макет HTML-отчёта**

\+------------------------------------------------------------------+

Если отличий нет, вместо «Отличия найдены.» выводится «Отличий нет.», а под заголовком «Различия» — фраза «Строковых различий нет.». Если папка и эталон пустые, сводка нулевая и добавлена фраза «Файлов нет. Папка совпадает с эталоном.»

Подписи статусов в отчёте русские: «без изменений», «изменён», «добавлен», «удалён». Внутренние значения в коде английские: unchanged, changed, added, deleted.

Номера строк в колонках — номера в списке splitlines(), начиная с 1\. У равной строки номер совпадает. У вставки и удаления номер относится к той стороне, где строка есть.

**3.3.4. Вёрстка и состояния отчёта**

•  Документ: \<\!DOCTYPE html\>, \<html lang="ru"\>, \<meta charset="utf-8"\>, заголовок окна «ClassConfig — отчёт сравнения».

•  CSS находится внутри \<style\>. Внешних файлов, шрифтов, картинок и скриптов нет. Файл открывается по пути file://.

•  Оговорка визуально отделена от сводки и стоит выше неё.

•  Успех без отличий и успех с отличиями — один и тот же шаблон. Меняются числа, фраза итога и наличие блоков различий.

•  Состояния «ошибка» и «загрузка» в HTML нет: ошибочный запуск файл отчёта не создаёт, а ожидание видно только как пауза в терминале.

•  Пустое состояние есть: пустая папка и успешная проверка без различий, как описано выше.

•  Цвета смысловые и спокойные: без изменений — нейтральный, изменён — янтарный, добавлен — зелёный, удалён — красный. Смысл не должен держаться на одном только цвете: рядом всегда есть текстовый статус.

•  Символы \<, \> и & из конфигов видны в браузере как символы, а в исходнике HTML записаны как сущности.

**3.4. Учебные файлы и обязательный сценарий**

В архиве есть demo/config. Каталогов demo/baseline и файла отчёта в архиве нет: их создаёт демонстрация. Перевод строки в учебных файлах — LF, файл заканчивается переводом строки. Кодировка UTF-8.

| Файл | Содержимое логических строк |
| :---- | :---- |
| app.ini | PORT=5432 / HOST=127.0.0.1 |
| display.conf | THEME=light |
| logging.conf | LEVEL=info |
| cache.conf | ENABLED=true |
| network.conf | TIMEOUT=30 |

Шаги демонстрации на Ubuntu, без root:

1\.  Запустить snapshot в demo/baseline. Ожидается код 0 и пять файлов.

2\.  Запустить check в demo/report.html. Ожидается код 0 и счётчики 0, 0, 0, 5\.

3\.  В app.ini заменить строку PORT=5432 на PORT=5433. Удалить display.conf. Создать extra.conf с одной строкой NOTE=demo.

4\.  Повторить check. Ожидается код 1 и счётчики 1, 1, 1, 3\. В отчёте изменён app.ini, добавлен extra.conf, удалён display.conf. Три остальных файла без изменений. У app.ini в колонках «Было» и «Стало» видны PORT=5432 и PORT=5433.

5\.  Удалить extra.conf и вручную вернуть app.ini и display.conf. Повторить check. Ожидается код 0 и счётчики 0, 0, 0, 5\.

Отдельная проверка экранирования, на копии папки или во временном каталоге теста: файл со строкой TITLE=a\<b\>\&c. В браузере виден текст TITLE=a\<b\>\&c. В исходнике HTML нет сырой последовательности a\<b\>.

**4.3. Ключевые инварианты**

Четыре темы, критичные для понимания системы.

1\.  Потоки. snapshot только пишет новый каталог. check читает папку и эталон и пишет один HTML снаружи. Оба потока при ошибке ничего не подменяют в уже существующих данных.

2\.  Сложное место сравнения. Пара файлов выбирается только по имени. Переименование — это удаление плюс добавление. LF и CRLF для одинаковых логических строк отличием не являются. Повреждённый эталон — это BASELINE\_CORRUPT, а не статус файла.

3\.  Сложное место ввода. Любая ссылка, вложенная папка, двоичные данные, чужая кодировка или лишний размер останавливают всю команду. Такой объект нельзя тихо пропустить и нельзя пометить как «без изменений».

4\.  Смысл отчёта. Код 1 означает «отличия найдены», а не «программа сломалась». Текст отчёта не означает, что служба исправна или что настройки нужно откатить. Отката в продукте нет.

Для работы нужны компьютер или виртуальная машина Ubuntu 22.04, Python 3.10 или новее и браузер. Внешние сервисы подключать не нужно.

**5\. Нормативные решения, которые нельзя трактовать заново**

•  Команды ровно две: snapshot и check. check всегда и сравнивает, и пишет отчёт.

•  Существующий путь эталона не перезаписывается. Для нового снимка указывается новый путь.

•  Отчёт при повторном check заменяется, если по пути лежит обычный файл.

•  Неподдерживаемый объект или ошибка чтения делают весь запуск неуспешным: кода 0 и кода 1 нет, HTML не пишется.

•  Сопоставление имён точное. Поиск переименований не реализуется.

•  Сравниваются логические строки splitlines(), а не сырые байты перевода строки.

•  Права, владелец и время файлов в сравнение не входят.

•  Программа не объясняет смысл параметров конфига и не объявляет систему исправной.

•  Сторонние пакеты, сеть, база данных, root и интерактивные вопросы не добавляются.
